# MCU UI polish — approved implementation

Date: 19 October 2026. Scope: frontend presentation and local list filtering.

## Direction and source

The owner approved the proposal inspired by `competition/caliber2026/website`. Adapt its 4px spacing scale, limited radii, text hierarchy, and restrained controls. Preserve MCU's green palette, locally hosted Montserrat, existing navigation and clinical workflows. The reference's blue palette, sidebar and two-level filter interface are not reproduced. Only design-taste-frontend was used for UI direction; Impeccable was not used.

Graphify located the shared table and master-detail components. Its graph predates some changes, so the relevant current source files were checked directly. This task does not rebuild the graph.

## Shared foundation

- Tokens in `frontend/src/app/globals.css`: spacing 4/8/12/16/20/24/32px; panel radius 12px, controls 8px, status 6px; stronger control borders than decorative panel borders.
- Keep green `#0E803F`, dark green `#156438`, canvas `#EFF7F3`, white panels, text `#172033`, muted text `#4F5F56`, maroon `#8B1C1A`, and restrained gold.
- Internal page titles 28px (24px mobile), panel titles 18px, table text 14px, labels 13px. Patient body text remains 16px.
- `WorkPanel` is the main white container for heading, controls and records, with 20px padding (16px mobile). `RecordTable` has a separator rather than a second rounded desktop container.
- Desktop detail pane is 320px beside the table from a 1280px viewport / 1200px page container. Smaller widths retain the existing accessible dialog. This preserves table space on laptops.

## Reusable filters

`StatusFilter` is now a shared client component with a styled select-only combobox and styled listbox. It replaces the existing radio-chip filters wherever the shared component was already used; screen-specific filtering logic remains with each owner.

Keyboard behavior: Enter/Space opens; arrows, Home and End move the active option; Enter/Space commits; Escape cancels; Tab dismisses and continues navigation. Typing an option prefix previews a match. Focus stays on the trigger while open; active options are announced through `aria-activedescendant`. Click outside or blur closes the list. Counts come from caller data; no numbers are invented.

`TableFilters` composes a search field, labelled selector, result count and conditional reset action. Its label can describe status, unit or message kind; an additional selector supports feedback ratings. Search/filter state is controlled by the screen, not by a new data layer. Copy lives in `src/content/internal.ts`.

## Two initial screens

### Draft hasil MCU

Search by patient name or queue identifier, case-insensitive and trimmed. Status combines with search. Option counts reflect search matches before applying the status filter; the result count reflects both. Existing five columns and verification actions remain. If the selected record is excluded by the filter, its detail/actions are not displayed.

### Permohonan surat keterangan

Search by patient name or registration reference with the same filter behavior. Columns: patient, registration reference, purpose, status and action. Phone remains available in the detail instead of occupying a list column. Existing letter editing/validation actions remain.

Both screens distinguish a genuinely empty list from no matching results and allow reset. The search covers their currently loaded local records; no claim is made about searching an entire future server dataset.

## Additional matching tables

### Worklist per unit

The same panel now combines patient-name/queue search and a styled unit selector. Counts in the unit selector reflect the searched visits, and reset clears both controls. All ten existing clinical/time columns remain. The upper daily and per-unit summaries continue to describe the full day; local list search does not change those totals. The selected unit still highlights the corresponding summary row. At 320px, summary table labels wrap within their container instead of overflowing the page.

### Kepuasan dan aduan

Search message text or its displayed date, then combine message kind and rating. Both dropdowns use the same styled control. Kind counts respect search and rating; the result count reflects all three controls. Reset works even when only rating is selected. Filtering out the selected record removes its detail; mobile filter changes close any open detail sheet. The heading's average remains the overall average, independent of local list filters.

The filter row wraps when necessary and becomes a single column on phones. In table panels the selectors use a 14rem flex basis to keep multiple controls together when space permits.

## Boundaries

No backend, registration, capacity, payment, identity, authorization, or medical scheduling changes. No new dependency. No real patient data added. Existing synthetic records remain the basis of UI checks. No demo/simulation/use-case labels are introduced into rendered UI.
